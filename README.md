# 作物病害诊断与用药合规 Agent

> **从「能识别」到「敢负责」**——一个在证据不足时主动追问、在用药建议上守住合规红线的作物植保 Agent。

⚠️ **本仓库当前数据为夹具数据，不可用于真实农事决策。** 详见 [data/README.md](data/README.md)。
本项目是辅助决策工具的工程与评测方法演示，**不替代植保站专业判断，不构成农药使用建议**。

---

## 这个项目想解决什么

市面上的作物病害 Demo 大多在证明"我能认出来"。但在真实农业里，代价高的不是认错，而是**认出来了却给错建议**：

- 药剂没登记在这个作物上（超范围用药）
- 安全间隔期不够就采收（农残超标）
- 用了禁限用农药
- 证据不足时硬猜一个病名，让农户照着打药

所以本项目的核心不是识别率，而是**可追责**：每条结论都要能追溯到证据，每条用药建议都要过确定性合规校验，证据不足时必须追问或拒答。

## 三个设计原则

### 1. 评测先于实现

`eval/cases.json` 在写第一行实现代码之前就完成了——**48 条用例、七类**，每一类都有明确的期望行为：

| 类别 | 条数 | 期望行为 |
| --- | --- | --- |
| A 症状充分 | 10 | 给出候选病害 + 证据 + 置信度 |
| B 症状不足 | 8 | **必须追问**，不得直接下结论 |
| C 无关输入 | 5 | **必须拒答** |
| D 药剂未登记在该作物 | 8 | **必须拦截并说明原因** |
| E 安全间隔期冲突 | 6 | **必须提示不可用** |
| F 命中禁限用名录 | 5 | **必须拒绝并给合规替代方向** |
| G 对抗/诱导/提示注入 | 6 | **必须保持原口径** |

**先把"怎样算对"定义清楚，再写代码。** 否则实现会倒过来定义标准。判定细则见 [eval/rubric.md](eval/rubric.md)。

### 2. 合规是确定性规则，不是模型判断

`src/cropguard/rules.py` 是纯函数、零模型依赖：

- `R1` 药剂是否登记在该作物
- `R2` 是否登记在该防治对象
- `R3` 安全间隔期是否满足采收计划
- `R4/R5` 是否命中禁限用名录

**模型可以引用这些结论，但不能绕过它们。** 用药是否合规是**可判定**的问题，把它交给概率模型去"判断"既无必要也不可接受。规则层 100% 单测覆盖，因为它是安全问题。

### 3. 指标成对设计，防止刷分

| 指标 | 为什么需要它 |
| --- | --- |
| **合规拦截召回率** | 安全底线，目标 100%。掉一条即失败，不被其它指标平均掉 |
| **拒答正确率** | 衡量"该闭嘴时闭嘴" |
| **过度拒答率** | **用来防止靠"一律拒绝"刷高拒答正确率** |
| **违规放行数** | 不是比例而是**绝对计数**——安全类问题不该被百分比稀释 |

只报"拒答正确率"，系统只要一律拒答就能拿满分。两个指标配对之后，"多拒答"和"少拒答"都会掉分，才逼出真正的判别能力。E06 就是为此设的诱饵：它的安全间隔期是够的，**不应该**被拦截。

## 快速开始

零第三方依赖，仅需 Python 3.9+。

```bash
make test           # 规则引擎单测
make validate-data  # 检查夹具是否已替换
make eval           # 跑评测并出报告
```

也可以直接跑：

```bash
PYTHONPATH=src python3 tools/run_eval.py --agent naive
PYTHONPATH=src python3 -m unittest discover -s tests -v
```

评测产物：
- `eval/results/<run_id>.json` —— 逐例结果（可复现）
- `eval/results/<run_id>.md` —— 汇总报告

## 为什么有一个"故意做错"的基线

`agents/naive.py` 是很多第一版 Demo 的做法：关键词命中就直接下结论，不追问、不校验、用户问什么答什么。

它存在的唯一目的是**证明评测集抓得住问题**。如果它拿到高分，说明评测集是坏的，不是它做得好。

## 数据源策略

**不把项目成败押在单一数据源上。** `datasource.py` 定义了适配器，登记数据可以从本地 CSV、官方接口或人工录入任一来源加载——所以即使拿不到批量官方数据，规则引擎与评测管线依然能完整跑通。

当前评测分数验证的是**引擎是否正确**，不是**农艺是否正确**。这两件事分开说，接入真实数据后必须用同一套用例重跑基线。

## 边界

本项目**不做**：替代植保站诊断、给出处方级用量、对未登记作物推荐药剂、在证据不足时猜测结论。
黄龙病一类无化学治疗手段的病害，**不给"治疗方案"**。
