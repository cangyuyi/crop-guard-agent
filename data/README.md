# ⚠️ 数据状态：本目录全部为**夹具数据（fixture）**，不可用于真实农事决策

本目录下的 CSV 用于**验证规则引擎与评测管线**，不是权威农艺数据，也不是真实农药登记数据。

## 逐文件说明

| 文件 | 是什么 | 可信度 |
|---|---|---|
| `diseases.csv` | 病害—症状知识表，症状描述取自公开植保教科书的**常识性表述** | 症状描述是教科书级别的通用知识；**但不构成诊断依据** |
| `registrations.csv` | 农药登记明细（作物/防治对象/安全间隔期） | **全部为夹具**。登记证号一律以 `FIXTURE-` 开头，**故意不采用真实登记证号格式**，避免被误认 |
| `banned.csv` | 禁限用农药名录 | **仅为占位**。条目方向性正确，但**必须以农业农村部最新公告为准**，当前版本未经核对 |

## 为什么这样设计

这个项目的定位是**「可追责」**：每条用药建议都必须能追溯到登记数据与法规依据。所以数据层必须可替换——

`src/cropguard/datasource.py` 定义了数据源适配器，登记数据可以从本地 CSV、官方接口或人工录入任一来源加载。**这意味着拿不到批量登记数据时，规则引擎与评测管线依然可以完整跑通**，数据源后续替换即可。

## 接入真实数据前必须做的事

1. 用官方登记数据替换 `registrations.csv`：登记证号改为真实编号，并补 `source` 字段记录来源与抓取/录入日期
2. 核对 `banned.csv` 与农业农村部最新禁限用公告，更新 `source` 字段
3. **用同一套 `eval/cases.json` 重跑基线**——因为 D/E/F 三类用例的判定依赖登记数据，换数据必然改变分数，旧基线随之失效
4. 运行 `make validate-data` 检查是否还有未替换的 `FIXTURE-` 记录

> 换句话说：**当前评测分数验证的是"引擎是否正确"，不是"农艺是否正确"。** 这两件事必须分开说，不能混为一谈。
