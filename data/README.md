# 数据状态与来源声明

## ⚠️ 两个必须知道的前提

**一、这些数据不能用于真实农事决策。**
本目录是面向**工程与评测方法**演示的数据快照，不是权威发布，**不构成农药使用建议**。
用药前请以手中产品标签与当地植保站指导为准。

**二、数据来自官方公开查询系统，但本站声明保留权利。**

登记数据取自**中国农药信息网**（主办单位：农业农村部农药检定所）的公开查询系统：

| 步骤 | 接口 |
| --- | --- |
| 按作物+防治对象查登记 | `/BasicDataSystem/pesticideRegistration/queryselect.do` |
| 登记详情 | `/BasicDataSystem/pesticideRegistration/viewpd.do?id=<uuid>` |
| 核准标签 | `/BasicDataSystem/pesticideRegistration/tagview.do?pdno=<登记证号>` |

> 该站页脚声明：**「网站保留所有权, 未经允许不得复制, 镜像」**

因此本仓库的处理方式是**引用与可复核**，不是转载：

- 只提交**目标子集的小快照**（查询台账约 40 行、登记记录 21 行），不做批量抓取与全量镜像
- **每一行都带 `source` 与 `fetched_at`**，可回到官方系统逐条核对
- 数据归属原作者；使用者应按需自行到官方系统查询最新值

## 逐文件说明

| 文件 | 是什么 | 可信度 |
| --- | --- | --- |
| `verified_queries.csv` | **官方登记查询台账**。(作物, 有效成分[, 防治对象]) 维度的查询结果与命中条数 | **R1/R2 判定的唯一依据。** 查询返回 0 条即为官方系统里确实没有——不靠推导、不靠猜测 |
| `registrations.csv` | 登记记录快照，含登记证号、产品名、有效成分、作物、防治对象、**间隔期抽取结果** | 记录本身来自官方标签页；间隔期为**文本抽取**结果，见下方缺口说明 |
| `diseases.csv` | 病害—症状知识表 | 症状描述取自公开植保教科书的**常识性表述**；**不构成诊断依据** |

## ⚠️ 数据缺口：间隔期只抽取到一部分

`make validate-data` 会如实报告。当前状态：

- 21 条登记记录中，**安全间隔期已抽取 7 条，未抽取 14 条**
- 原因：间隔期写在核准标签的**自然语言**里，且**按作物分列**，不存在结构化字段
  （例：「在苹果树上的安全间隔期为21天……在番茄上的安全间隔期为3天」）

**这直接决定了引擎的形态**：`rules.py` 里有一条 `R3_PHI_UNKNOWN`——
间隔期未知时**既不拦截也不放行**，而是转人工核对标签。
把"没查到"当成"没问题"，是这个场景里最危险的做法。

## 数据缺口导致的设计取舍（应当知道的）

因为快照是**抽样**而非全量：

- **R1（是否登记在该作物）可以拦截**——作物级查询是**穷尽**的，返回 0 条就是确实没有
- **R2（是否登记在该防治对象）也可拦截**——防治对象级查询同样穷尽，
  但只在**查过**的组合上有结论；没查过的组合会转人工，不会当通过
- **"快照里没有"不构成未登记的证据**——这是 `check_target_disease` 里明确处理的分支

## 数值的真实发现（写进设计的两条）

1. **间隔期按登记证号存在，不按成分存在。**
   甲基硫菌灵在番茄上：`PD20111255` = 3 天，`PD20161283` = 7 天。
   → 规则 `R3_PHI_MULTI`：多值冲突时不给单一数字，要求核对产品标签。

2. **混剂要按可查的有效成分核对。**
   `唑醚·代森联` 作为整体查是 0 条，但其组分 `吡唑醚菌酯` 在柑橘上有 109 条。
   采集脚本必须把商品名与有效成分分开处理，否则会得出错误的"未登记"结论。

## 刷新数据

```bash
python3 tools/validate_data.py     # 体检：多少间隔期未知、多少组合未登记
python3 tools/parse_phi.py < 标签全文.txt   # 单独跑一次间隔期抽取
```

接入新的登记数据后，**必须用同一套 `eval/cases.json` 与 `eval/holdout.json` 重跑基线**——
D/E/H 三类的判定依赖这些数据，换数据必然改分，旧基线随之失效。
